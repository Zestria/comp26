## Представление

Выдели `imm` (константы и имена), `compound` (одна операция с атомарными
операндами) и `term` (let-цепочка с результатом). Условие `if` атомарно,
но его ветви — полноценные ANF-термы. Например:

```ocaml
(* исходное: (5 + 4) - 2 *)
(* ANF: let t0 = 5 + 4 in let t1 = t0 - 2 in t1 *)
```

Конкретный набор конструкторов зависит от IR: lambda может быть отдельной
операцией, а после closure conversion — созданием closure. Не требуй ровно
одного представления для всех стадий. Типы ANF должны запрещать вложенные
неатомарные аргументы конструктивно, а checker — проверять scope и arity.

## Нормализация через continuation

`normalize env expr k` передаёт атомарный результат в `k : imm -> term`.
Константа/имя вызывают `k`; сложная операция нормализует операнды,
создаёт свежий temporary, связывает результат и вызывает `k` с его именем.
Так let-цепочки строятся без повторяющегося извлечения хвостов дерева.
В слайдах промежуточный код намеренно неполон и порядок аргументов меняется:
ориентируйся на тип функции, а не на буквальное копирование.

[examples/anf_example.ml](examples/anf_example.ml) — компилируемый пример
для int, addition, nonrecursive let и if. В этом игрушечном языке условие
целочисленное (0 — false), порядок вычисления слева направо; это не семантика
bool-условия MMML. Пример резервирует все исходные имена, переименовывает
связанные переменные и хранит fresh counter внутри одного преобразования.
Он также содержит независимые интерпретаторы исходного и ANF деревьев.

## Важные случаи при переносе в MMML

- `let x = rhs in body`: rhs вычисляется в старом окружении, body — с новым
  binding. Shadowing нельзя превращать в захват свободных переменных.
  Для `let rec` область видимости другая: recursive binder доступен и в rhs;
  обработай recursion отдельно с учётом представления функций.
- Fresh names не должны совпадать с пользовательскими, свободными или
  уже созданными именами. Один лишь префикс `tmp` не гарантирует свежесть.
  Alpha-renaming либо уникальные внутренние IDs упрощают дальнейшие проходы.
- В `if` нормализуй condition до ветвления; вычисления ветвей остаются внутри
  соответствующих ветвей. Можно связать результат compound `If` одной let,
  как в примере; при CFG IR можно использовать join point/phi по контракту IR.
  Не дублируй большое продолжение в обеих ветвях.
- В MMML `Application` бинарен, функции каррированы. Не превращай
  `((f a) b)` в один вызов с двумя аргументами без сведений об arity и
  эффекте промежуточного применения.
- `Ast.infix` строит обычное применение имени оператора. Обрабатывай `+`
  как primitive только после разрешения binding: пользователь может затенить
  имя. Аналогично сохраняй short-circuit поведение `&&`/`||`, если оно входит
  в контракт языка, вместо безусловного вычисления обоих аргументов.
- Lambda body нормализуется внутри lambda; вычисления из него нельзя вынести
  в место создания функции. Свободные переменные сохраняют привязки.

## Проверки

Проверяй структурную ANF-форму, scope, отсутствие захвата, типы (для typed IR)
и сохранение вычисляемого результата. Для языка с эффектами сравнивай также
последовательность эффектов и ошибки; числовое равенство само по себе слабо.
Фиксированные примеры: nested let и shadowing, обе ветви if, свободное имя
`anf0`, wildcard binding с эффектом, recursion и частичное применение.
Сравнивай IR с точностью до alpha-equivalence, если fresh-name spelling не
является публичным контрактом. Не требуй побуквенной идемпотентности прохода,
который меняет представление AST на другой тип IR.

Пример имеет исполняемые QCheck properties:
[examples/anf_qcheck.ml](examples/anf_qcheck.ml). Инструкции запуска находятся
в [qcheck.md](qcheck.md). Он не покрывает функции, recursion и эффекты MMML;
для реального прохода генераторы и семантический oracle нужно расширить.
