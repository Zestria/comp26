1    Регистры
   Регистры процессора — это небольшие области сверхбыстрой па-
мяти внутри процессора, используемые для временного хранения дан-
ных, адресов и промежуточных результатов вычислений.
   Регистры различаются в зависимости от архитектуры процессора:

    • по назначению: целочисленные (GPR), для чисел с плавающей
      точкой (FPU), SIMD/векторные (MMX/SSE/AVX/NEON), специ-
      альные (счётчик стека, базовый указатель, счётчик команд и т.п.);

    • по разрядности и взаимному наложению (aliasing): например, в
      x86-64 регистры AL, AX, EAX, RAX ссылаются на один и тот
      же физический регистр разной ширины, что наглядно показано
      на Рис. 1.

    • по доступности: некоторые регистры зарезервированы (напри-
      мер, RSP под стек в x86-64), часть — должна сохраняться по со-
      глашению о вызовах (callee-saved), а часть может быть «испор-
      чена» вызовом (caller-saved);

                                           1
    • по архитектурным ограничениям инструкций: отдельные инструк-
      ции требуют конкретные регистры (например, MUL/IMUL/IDIV
      в x86 используют RAX/RDX), либо регистровые пары/выравнивание.

   У нас есть память имеющая быстрый доступ (доступ к регистрам
гораздо быстрее, чем к оперативной памяти), но есть проблема — ее
мало и хочется максимально эффективно использовать это ограничен-
ное пространство, чтобы сократить операции загрузки и выгрузки дан-
ных из памяти, тем самым ускорив работу программы.


2    Распределение регистров
   Распределение регистров — это процесс выбора, какие перемен-
ные и промежуточные значения программы будут храниться в реги-
страх процессора, а какие — в оперативной памяти.
   В промежуточном представлении обычно неограниченное количе-
ство виртуальных регистров. А у конкретного процессора их конкрет-

регистры по физическим.
   Для решения этой задачи используются различные алгоритмы. В
данном конспекте рассматриваются алгоритмы LinScan и Puzzle solving.

2.1     Основные понятия
    Перед тем как переходить к алгоритмам, необходимо ввести несколь-
ко основных определений.
    Переменная считается живой в некоторой точке программы, если:
      • она уже была определена (ей присвоено значение);
      • и существует путь исполнения, при котором значение из нее мо-
        жет быть прочитано (использовано) до следующего присваива-
        ния.
    Промежуток активности переменной (live range) — это множе-
ство точек в программе, где переменная живая. Важно отметить, что
live range может быть несвязным, то есть содержать ”дыры”, когда пе-
ременная временно не используется.
    Интервал активности переменной (live interval) — это непрерыв-
ный отрезок от первого определения переменной до её последнего ис-
пользования в программе. Интервал активности является упрощением
промежутка активности. Даже если в середине этого отрезка есть ”ды-
ры ,̈ где переменная неживая, интервал всё равно считается непрерыв-
ным.
    Наглядно разницу между промежутком и интервалом активности
демонстрирует Рис. 2.

    Spilling — процесс выгрузки содержимого переменной из регистра
в память, когда не хватает доступных регистров для хранения всех ак-
тивных переменных.

2.2     LinScan
    Хочется получать ответ более-менее быстро (например, для JIT-
компиляции). Для этого часто используются линейные алгоритмы. Один
из них — LinScan.
    Суть алгоритма заключается в линейном проходе по списку интер-
валов активности переменных и попытке назначить каждой перемен-
ной регистр таким образом, чтобы минимизировать количество обра-
щений к памяти, т.е. уменьшить количество операций spilling.

2.2.1   Алгоритм
    Перед работой алгоритма для каждой переменной вычисляется её
интервал активности (этот этап может быть выполнен за один проход
по графу потока управления). Эти интервалы сортируются по времени
(номеру инструкции) начала их жизни.
    Алгоритм обходит отсортированные интервалы один за другим и
выполняет следующее:
   1. Перед обработкой нового интервала освобождаются все регистры,
      занятые интервалами, которые уже завершились;
   2. Назначается регистр:
         • Если доступен свободный физический регистр, он назнача-
           ется текущему интервалу;
         • Если свободных регистров нет, вызывается процедура вы-
           теснения (spilling) — интервал с наименьшим приоритетом
           (например, с наибольшим временем жизни или меньшей
           частотой использования) сохраняется в памяти, чтобы осво-
           бодить регистр;
    Рассмотрим несколько примеров (примеры взяты из Стэнфордско-
го курса [3]).

2.2.3   Плюсы и минусы
   Преимущества:
      • Очень эффективный (после вычисления интервалов активности
        работает за линейное время);
      • Простота реализации;
      • Предсказуемость поведения;
      • Один проход, можно порождать код по мере интерпретации;
      • Часто используется при JIT-компиляции.
Недостатки:
      • Неточен, т.к. используются интервалы вместо промежутков ак-
        тивности;
      • Меньшее качество распределения — по сравнению, например, с
        графовыми методами, LinScan может давать большее количество
        spill’ов;
      • Отсутствие глобального анализа — не учитывает конфликты ре-
        гистров на больших участках кода, что может снизить произво-
        дительность.

2.3.1   Состав игры
   Головоломка состоит из:
    • Игрового поля — это наше множество физических регистров.
    • Набора деталей (пазлов) — это переменные программы, которые
      нужно разместить.
    • Правила игры — это ограничения, которые нельзя нарушать (на-
      пример, наложения жизненных интервалов, архитектурные тре-
      бования, зарезервированные регистры).
   Детали не могут перекрываться на игровом поле, и часть деталей
уже размещена на нём (например, могут существовать зарезервирован-
ные регистры). Задача состоит в том, чтобы разместить оставшиеся
детали на игровом поле.

2.3.4   Подготовка к игре
   Перед началом игры происходит:
   1. преобразование исходной программы в элементарную форму;
   2. сопоставление элементарной формы с деталями головоломки.

2.3.5   Элементарная форма
   Прежде чем приступить к решению головоломок, исходную про-
грамму необходимо преобразовать в элементарную форму. Это спе-

                                                  23
циальное представление программы, являющееся подмножеством SSA-
формы (Static Single Assignment), в котором диапазоны жизни пере-
менных содержат не более двух программных точек.
   Идея: разбить глобальную задачу распределения регистров на по-
следовательность локальных головоломок.
   В результате преобразования каждая переменная активна не более
чем в двух последовательных точках программы.
   Преобразование любой программы в элементарную форму выпол-
няется за три шага:

  1. Преобразование в SSA-форму.
     На этом шаге все переменные переименовываются для обеспе-
     чения уникальности каждого присваивания. В точки слияния по-
     токов управления (например, в начале циклов или после услов-
     ных операторов) вставляются φ-функции для объединения раз-
     личных версий одной и той же переменной.

  2. Преобразование в SSI-форму (Static Single Information).
     Этот шаг является обратным к предыдущему. В точки ветвления
     потока управления (например, в конце базовых блоков) добавля-
     ются π-функции. Они являются двойственными по отношению
     к φ-функциям: если φ-функции объединяют потоки значений, то
     π-функции, наоборот, разделяют их, создавая новые версии пе-
     ременных для каждой из ветвей.

  3. Вставка параллельных копий.
     Наконец, между каждой парой последовательных инструкций внут-
     ри базового блока вставляются операции параллельного копиро-
     вания с последующим переименованием переменных, активных
     в этой точке.

   Для каждой инструкции создается своя головоломка, где «детали» —
это переменные, активные в этой точке. Правила преобразования пе-

    • Деталь X: Если диапазон жизни переменной заканчивается на

      не нужно), она становится деталью X.
    • Деталь Z: Если диапазон жизни переменной начинается на теку-
      щей инструкции (она определяется здесь), она становится дета-
      лью Z.
    • Деталь Y: Если диапазон жизни переменной проходит сквозь ин-
      струкцию (она была активна до и остается активной после), она
      становится деталью Y.

повторное использование регистров. Регистр можно выделить под од-
ну переменную, жизнь которой заканчивается (деталь X в верхнем ря-
ду), и сразу же после этого — под новую переменную, жизнь которой
начинается (деталь Z в нижнем ряду). Деталь Y занимает обе ячейки,
показывая, что регистр занят на протяжении всей инструкции и не мо-
жет быть использован для других целей.
    Размер детали определяется типом соответствующей переменной.
Например, в архитектуре x86 8-битная переменная (требующая регистр

2.

2.3.9   Spilling
   Алгоритм обрабатывает программу инструкция за инструкцией. Ес-
ли головоломка для текущей инструкции имеет решение, распреде-
литель переходит к следующей. Однако, если головоломка нерешае-
ма (например, из-за нехватки доступных регистров), запускается ме-
ханизм сброса в память (spilling).
   Процесс является итеративным:

   1. Выбирается одна из переменных для выгрузки в память.
   2. Соответствующая ей деталь удаляется из набора.
   3. Предпринимается новая попытка решить головоломку.
   4. Этот цикл повторяется до тех пор, пока не будет найдено реша-
      емое состояние.

   Теперь вопрос в том, какую деталь удалить. Ну, во-первых, мы не
можем удалить детали X или Z, поскольку они представляют перемен-
ные, являющиеся непосредственными операндами текущей инструк-
ции (используемыми или определяемыми). Поэтому мы должны уда-
лить элемент Y.

                                      33
    Для выбора конкретной переменной из числа кандидатов исполь-
зуется эвристика Белади [6]: сбрасывается та переменная, следующее
использование которой в программе находится дальше всего. После
сброса переменная временно исключается из рассмотрения в после-
дующих головоломках до тех пор, пока она снова не потребуется для
выполнения какой-либо инструкции.
    Выбор эвристического подхода здесь не случаен. Как гласит теоре-
ма, задача определения оптимального набора переменных для сброса
является NP-полной. Поэтому вместо поиска вычислительно сложно-
го, но идеального решения, применяется быстрая эвристика.

    Теорема:
    Выделение регистров в присутствии предраскрашивания (pre-coloring)
и сброса (spilling) семейства переменных для элементарного представ-
ления — NP-полная задача.

2.3.10 Coalesing
    Важной задачей при распределении регистров является объедине-
ние (coalescing) — стратегия, направленная на минимизацию лишних
инструкций перемещения (copy, move). Ее суть заключается в том, что-
бы одна и та же переменная программы по возможности занимала один
и тот же физический регистр в смежных инструкциях. Если перемен-
ная перемещается из одного регистра в другой между двумя голово-
ломками, в код необходимо вставить дополнительную операцию ко-
пирования для сохранения корректности программы.
    Нахождение глобально оптимального распределения, которое ми-
нимизирует количество копий во всей программе, является NP-полной
задачей. Поэтому в данном подходе, нацеленном на высокую скорость,
применяется стратегия локального объединения.
    Механизм работает следующим образом:


                                34
   • Решение головоломки для текущей инструкции принимается с
     учетом распределения, полученного на предыдущем шаге, что-
     бы минимизировать количество перемещений между ними. Для
     этого обход программы выполняется в порядке, заданном дере-
     вом доминаторов.

   • Сложность локального объединения зависит от наличия пред-
     определенных регистров:

        – Если предопределенных регистров нет, задача решается за
          полиномиальное время.
        – При их наличии точный класс сложности неизвестен, и ис-
          пользуется эвристическая стратегия best-effort.

   Данный метод сознательно не стремится к глобальной оптимиза-
ции, так как основной целью является скорость распределения. Тем не
менее, предложенный фреймворк не исключает использования более
сложных, глобальных стратегий объединения в других реализациях.

2.3.11 Плюсы и минусы
   Преимущества:
   • Высокая производительность (для головоломок типов 0 и 1);

   • Учитывает архитектурные особенности.
Недостатки:
   • Неприменимость для некоторых архитектур (головоломки типа
     2 не имеют общего решения);

   • Локальный подход к решению (не учитывает глобальную карти-
     ну распределения);

                                35
• Глобально оптимальные spilling/coalescing недостижимы (NP-трудно);

• Требует сложной предварительной подготовки кода (преобразо-
  вание в элементарную форму).
