Заключение про ANF I

     ANF пригодится, когда дойдете до LLVM
     Можно написать много разных реализаций, самое нетривиальные
     места — let и if
     Часто будут появляться ненужные переменные, например,
     (let x1 = x3 in x1). Можно пытаться такое не порождать, а можно
     упрощать отдельным проходом
     В контексте miniML могут появляться каверзные случаи, типа
     (let temp1 = (+) x1 in temp1 x2) вместо (x1 + x2). Используя
     информацию об уже объявленных функциях, нужно не создавать такие
     ANF
                       pure   pure
     val (+): int −−−→ int −−−→ int

Заключение про ANF II


     У LLVM и ассемблера RISC-V есть специальные инструкции для
     сравнения и перехода. Поэтому программы получатся проще, если
     «инлайнить» let x = A < B in if x then ... в if A<B then ...
     Вывод: если сделать проверку типов (арность, стандартная ли это
     функция печати/сложения или пользовательская) до ANF, то будут менее
     «мусорные» ANF
     Недостаток: иногда рядом с if-then-else код копируется и размер
     программы «взрывается»
     Недостаток: не замкнута, относительное β-редукции, inlining затруднён
