Немного истории

       В 1950г. программировали на машинных кодах и на ассемблере
           Медленно и дорого
       В 1954 Д. Бэкус оттранслировал язык выражений в код мэйнфрейма IBM 7941
       Проект Fortran I (FORmula TRANslator) — первый компилятор

Последствия:
       Многие программисты опасались (опасаются), что языки высокого уровня
       ухудшают производительность
       Первый оптимизирующий компилятор
       Фортран оказали влияние на другие компиляторы
           Многие в него компилировались
           Делали архитектуру компилятора как в Фортране

Что такое компилятор

Определение
Компилятор — это системное ПО, которое транслирует программы с исходного
языка программирования в целевой язык


Типичные исходные языки: C, OCaml, C#...
Целевой (англ. target) язык — обычно инструкции процессора


Важные свойства компилятора:
    Порождать корректный код
    Улучшать код согласно некоторой метрике
    Помогать пользователю: сообщать о настоящих и потенциальных ошибках

Трансляторы из исходного кода в исходный код

Порождают код на другом языке программирования, вместо ассемблера процессора

   Ещё называют транскомпиляторы или transpiler’ы
   Например, Typescript ⇝ Javascript, или какой-нибудь модельный язык ⇝ Си

Чтобы исполнять скомпилированное, нужны ещё фазы трансляции

Антипример: LATEX⇝ PDF обычно считают компиляцией

              Transpiler                          Compiler
     Конвертирует между языками     Традиционный компилятор транслирует
       с примерно одинаковым              из языка высокого уровня
         уровнем абстракции                       в низкий

Нельзя просто взять и скомпилировать
Трансляция «в лоб» не всегда возможна
    Проблемы с абстракцией: абстрактные типы данных и переменные vs. память и
    регистры
    Поток управления vs. jump’ы
Некоторые языки дальше от железа, чем другие (например, ООП vs. Си)


Как действуют:
    Транслируют по шагам, где каждый отвечает за простую, четко поставленную
    задачу
    Получается серия промежуточных представлений (англ. intermediate
    representation, IR) для хранения информации. Представления можно
    переписывать для совершения оптимизаций
    По ходу трансляции IR становятся более похожи на машинный код, чем до этого

Части компилятора: Фронтенд (англ. frontend)


             «Олдскульный» подход: лексер и парсер какой-то грамматики
   Лексер (англ. lexer, лексический анализатор) разбивает вход на слова (англ.
          token)
   Парсер (англ. parser, синтаксический анализатор) объединяет слова в
          представление программы — дерево абстрактного синтаксиса
Генераторы синтаксических анализаторов: по грамматике дают парсер (ANTLR,
          Menhir)
Scannerless Можно и без лексера
  Вручную рекурсивным спуском

Оптимизации — это сложно



Для разных программ полезны разные оптимизации
(В идеале) Компилятор должен «настраиваться» под программы
   Выбор и порядок применения оптимизаций
   Параметры полезности оптимизаций (например, граница размера функции для
   inlining)
   Autotuning — автоматический перебор опций компиляции, чтобы получить
   получше результат
   Некоторые применяют ML

Планирование инструкций. Пример

 LOAD @ADDR1, @OFF1 −> R1                 LOAD @ADDR1, @OFF1 −> R1
 ADD R1, R1 −> R1                         LOAD @ADDR2, @OFF2 −> R2
 LOAD @ADDR2, @OFF2 −> R2                 LOAD @ADDR3, @OFF3 −> R3
 MUL R1, R2 −> R1
 LOAD @ADDR3, @OFF3 −> R2    ⟹            ADD R1, R1 −> R1
                                          MUL R1, R2 −> R1
 MUL R1, R2 −> R1                         MUL R1, R3 −> R1
 STORE R1 −> @ADDR1, @OFF1                STORE R1 −> @ADDR1, @OFF1

В предположении:
   LOAD/STORE — 3 такта
   MUL — 2 такта
   ADD — 1 такт
