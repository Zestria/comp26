# MMML: контракт C-рантайма для RV64

Рантайм предоставляет только общий механизм значений, замыканий, вызова и
запуска программы. Он не знает имён функций языка, операторов или внешних
функций. Компилятор пока не генерирует RISC-V ассемблер; C-тесты в этом
каталоге изображают сгенерированный код. `MMML/bin/runtime.c` относится к
отдельному старому LLVM-демо.

Сборщика мусора и протокола корней пока нет. Созданные замыкания выделяются
через `malloc` и освобождаются в `mmml_shutdown` после завершения программы.
Долгая программа потребляет память пропорционально числу созданных замыканий.
При добавлении GC потребуется отдельно согласовать корни с кодогенератором.

## Представление значений

`mmml_value` — 64-битное слово. Формат зафиксирован в [runtime.h](runtime.h):

| Значение | Представление |
| --- | --- |
| Целое в диапазоне `[-2^62, 2^62-1]` | `((uint64_t)n << 1) | 1` |
| Указатель на замыкание | Ненулевой адрес, кратный 8 |
| `false`, `true`, `unit` | `2`, `6`, `10` |

`0` не является значением языка. `mmml_int` проверяет диапазон, а
`mmml_unbox_int` отвергает нецелое значение. Для логических значений
используются `mmml_bool` и `mmml_unbox_bool`. При генерации `if`
нельзя проверять `value != 0`: `MMML_FALSE` тоже ненулевой.

## Замыкания и частичное применение

У тела сгенерированной функции одна сигнатура:

```c
typedef mmml_value (*mmml_code)(const mmml_value *args);
```

Массив `args` содержит аргументы в порядке применения и существует только
на время вызова. Замыкание содержит адрес кода, полную арность и ранее
переданные аргументы. Захваченные значения closure conversion ставит перед
исходными параметрами. Например:

```c
mmml_value f = mmml_make_closure(generated_code, 2);
mmml_value partial = mmml_apply(f, captured_x);
mmml_value result = mmml_apply(partial, y);
```

Первый `mmml_apply` создаёт новое замыкание; второй вызывает
`generated_code` с `args[0] == captured_x` и `args[1] == y`.
Исходное `f` можно применить снова: частичное применение не меняет
существующие замыкания. Если тело возвращает функцию, следующий вызов
`mmml_apply` работает с возвращённым значением. Кодогенератор должен
сохранять границы групп аргументов у вложенных `Lambda`.

Применение не-функции, нулевая арность и неизвестный адрес замыкания вызывают
ошибку. `mmml_is_closure` проверяет только тег адреса; `mmml_apply`
дополнительно проверяет принадлежность объекта рантайму.

Для RV64 действует стандартный
[RISC-V psABI](https://github.com/riscv-non-isa/riscv-elf-psabi-doc/blob/master/riscv-cc.adoc).
`mmml_make_closure(code, arity)` и `mmml_apply(function, argument)`
получают аргументы в `a0` и `a1`, возвращают результат в `a0`.
Косвенно вызываемый `mmml_code` получает адрес массива `args` в `a0`.
Сгенерированный код должен сохранять callee-saved регистры и выравнивать
стек по ABI.

## Операции языка и внешние функции

В рантайме нет таблицы встроенных функций и функций для арифметики,
сравнений, логических операторов или печати. Кодогенератор реализует
примитивные операции в сгенерированном коде. Если операция должна быть
значением первого класса, он создаёт для неё тело с сигнатурой `mmml_code`
и обычное замыкание через `mmml_make_closure`. Таким образом имена и
семантика конкретных операций не входят в контракт рантайма.

Короткое замыкание `&&` и `||` требует условной ветки: правую часть нельзя
вычислять заранее. Внешние функции должны разрешаться кодогенератором при
линковке; при отсутствии реализации он должен выдавать ошибку компиляции.
Символы внешних функций можно вызывать по стандартному C ABI через
сгенерированные обёртки. Печать и другие побочные эффекты принадлежат этим
обёрткам или внешним библиотекам, а не общему рантайму.

## Запуск и связывание

[startup.c](startup.c) определяет обычный C `main`. Сгенерированная
программа экспортирует один символ:

```c
mmml_value mmml_program_main(void);
```

Она исполняет определения верхнего уровня в исходном порядке. `main`
игнорирует возвращённое значение и вызывает `mmml_shutdown`.
`mmml_init` выполняется до входа в сгенерированную программу. Второй
`main` в ассемблере не нужен.

Пример связывания с `program.s`:

```sh
riscv64-linux-gnu-gcc -std=c11 -O2 -Wall -Wextra \
  MMML/runtime/runtime.c MMML/runtime/startup.c program.s -o program
qemu-riscv64 -L /usr/riscv64-linux-gnu program
```

`mmml_fail(message)` печатает сообщение в stderr и завершает процесс
с ненулевым кодом. Кодогенератор может использовать её для проверок
инвариантов и ошибок выполнения.

## Проверки и ограничения

```sh
dune build -p MMML @MMML/runtime/runtest --force
dune build -p MMML @check @runtest @install
```

Тесты проверяют теги, диагностику неверных значений, независимость
замыканий, частичное применение, CPS-факториал и запуск через `startup.c`.
Арифметика в тестовых функциях имитирует сгенерированный код. Для RV64:

```sh
riscv64-linux-gnu-gcc -std=c11 -O2 -Wall -Wextra -Werror -pedantic -static \
  MMML/runtime/runtime.c MMML/runtime/runtime_test.c -o /tmp/mmml-runtime-rv64-test
qemu-riscv64 /tmp/mmml-runtime-rv64-test
```

Это проверяет C ABI на RV64, но не заменяет интеграционный тест с
ассемблером MMML: backend ещё не подключён. Большие CPS-программы могут
исчерпать C-стек, потому что протокол хвостовых вызовов пока не реализован.
Heap содержит только замыкания; для tuples/lists понадобятся новые формы
объектов.
