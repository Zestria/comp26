# Proposal

## Why

MMML пока разбирает MiniML в нетипизированный AST, но не имеет промежуточного представления для следующих проходов компилятора. ANF сделает порядок вычислений явным, сохранит области видимости и подготовит функции к последующей closure conversion и lambda lifting.

## What Changes

- Добавить самостоятельную библиотеку middleend с ANF IR, API нормализации выражений и программ, проверкой инвариантов и диагностической печатью.
- Сохранить константы int/bool/unit, каррированные функции, application, if, обычные let и функциональную рекурсию текущего AST.
- Зафиксировать вычисление application слева направо: функция, аргумент, применение; встроенные полностью применённые `&&`/`||` используют короткое замыкание.
- Различать пользовательские bindings и встроенные операторы; не заменять затенённые операторы primitives.
- Уменьшать административные связывания и избегать копирования продолжений в ветви if без изменения эффектов и ошибок программы.
- Добавить регрессии и QCheck-проверки формы, scope и семантики, включая CPS-факториал и Fibonacci.

## Capabilities

### New Capabilities

- `mmml-anf`: преобразование MiniML AST в компактный ANF с сохранением порядка вычислений, короткого замыкания и лексических привязок.

### Modified Capabilities

Нет: существующих основных спецификаций в проекте пока нет.

## Impact

Новые модули и Dune library под `MMML/lib/middleend/`, новые тесты под `MMML/test/`; входом остаётся `Ast.expr`/`Ast.program` из `MMML.frontend`. Новые внешние зависимости не требуются. Контракты сборки `dune b -p MMML` и тестирования `dune test -p MMML` сохраняются.

В этом изменении не реализуются вывод типов, closure conversion, lambda lifting, LLVM/RISC-V backend или новые синтаксические конструкции. Полный набор CLI-опций из задания, включая `--stop-after anf`, остаётся отдельной интеграционной работой; ANF доступен через библиотечный API и printer. Самостоятельный ANF-проход не является завершением всего задания Middleend.
