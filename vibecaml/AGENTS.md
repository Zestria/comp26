# vibecaml — правила для агентов и людей

Корневой `AGENTS.md` — это ТЗ, он приходит из апстрима: **не редактировать**. То же с `demo/`, корневым `Makefile`, `teams.yml`, `.sourcecraft/ci.yaml`

## Стиль кода

Комментарии и докстринги — **по-русски**.
На каждый модуль библиотеки — **`.mli`**. Докстринги в нём, `.ml` комментируем только там, где неочевидно «почему так».
Ошибки наружу — **`('a, string) result`**, не исключения. Внутри реализации исключения можно, но их ловим на границе модуля.
Формат — ocamlformat, профиль janestreet; настройка в корневом `.ocamlformat`.

## Работа

Задачи — в issues на SourceCraft, не в файлах репозитория.

## Коммиты

Conventional Commits: `<тип>(<область>): <описание>`.
Описание — по-русски

```
feat(parser): добавить разбор let ... in
fix(lexer): не глотать перевод строки после комментария
chore(make): вынести цели сборки в vibecaml/Makefile
```

## Перед PR и пушем

Прогнать из `vibecaml/`, в этом порядке:

```
make fmt-check   # форматирование не разъехалось
make release     # dune build -p vibecaml
make test        # dune test -p vibecaml
make lint        # Zanuda; если не установлена, цель подскажет команду установки
```

Красный `fmt-check` чинится через `make fmt`. Полный список целей — `make help`.

Коммитить только то, что относится к задаче: переформатирование чужих файлов
и правки вне `vibecaml/` в тот же PR не попадают.

## Агентам отдельно

* Не писать код по задачам из ТЗ без явной просьбы — их разбирают люди.
* Не выходить за пределы `vibecaml/` без явной просьбы.
* Не пушить и не открывать PR без явной просьбы.
