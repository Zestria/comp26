# RISC-V: тулчейн, запуск, отладка

Контракт с рантаймом — `adr/0003-riscv-contract.md`.

## Установка

    sudo apt install binutils-riscv64-linux-gnu gdb-multiarch qemu-user

Тесты `test/riscv/qemu.t` включаются сами, когда в PATH есть `qemu-riscv64`.

## Запуск

    vibecamlc prog.ml -o prog.s
    scripts/run.sh prog.s        # или: make run PROG=prog.s

`scripts/run.sh` собирает `prog.s` и `runtime/runtime.s` через `as` и `ld` и
запускает результат под QEMU.

Пример из корня репозитория после подключения Codegen (#21):

```sh
opam exec --switch=comp26 -- dune exec vibecaml/compiler.exe -- \
  vibecaml/test/middleend/fack.src -o /tmp/fack.s
sh vibecaml/scripts/run.sh /tmp/fack.s
```

Результат — `120`. Для `fibk.src` — `55`. Режим по умолчанию совпадает
с `--stop-after asm`; `--stop-after anf` по-прежнему печатает промежуточный ML.

В `test/codegen/` снапшоты `.s` проверяются всегда. QEMU-тесты включаются,
когда доступны QEMU, `as` и `ld`: сравнивают весь stdout с OCaml на обоих
парсерах, проверяют ошибки runtime и ABI. `test/codegen_test.ml` отдельно
проверяет ограничения кадра, неизвестные имена, поля кортежа и линейность
цепочки `if`. Кодоген не реализует типизацию: сравнения предназначены
для целых и bool, float и структурное сравнение кортежей не поддерживаются.

## Ограничение памяти

Рантайм выделяет фиксированную кучу в 1 МиБ. Она не растёт, сборщика мусора
нет: даже уже ненужные замыкания занимают место до конца процесса. Поэтому
большой CPS-пример может закончиться сообщением `Error: not enough memory
on heap` и кодом 1. Это предел текущего рантайма, а не поддержка произвольных
`n`: например, `fibk 20` даёт `6765`, а `fibk 25` исчерпывает кучу.

Кортежи и замыкания проверяют конец нового блока до записи. QEMU-тесты
проверяют точное заполнение маленькой тестовой кучи, следующую аллокацию
за её границей и большие CPS-входы. Стек тоже конечен: оптимизация хвостовых
вызовов относится к заданию 5 и пока не реализована.

## Отладка

В одном терминале:

    scripts/run.sh -g 1234 prog.s

QEMU ждёт отладчик, а бинарь с символами кладётся в `./a.out`. Во втором:

    gdb-multiarch a.out -x tests/.gdbinit

`.gdbinit` подключается к `:1234`, показывает регистры и ставит точку
останова на `_start`. Дальше: `si`/`ni` — шаг по инструкции с заходом в вызов
и без, `b vc_main`, `c`, `info registers a0`, `x/8xg $sp` — 8 слов со стека.
