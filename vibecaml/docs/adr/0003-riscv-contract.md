# 0003. Контракт сгенерированного кода с рантаймом

Статус: принято в #19. Рантайм — #20 (`runtime/runtime.s`), кодоген — #21.
Имена символов взяты из рантайма; в тексте #19 были другие (`print_int`,
`vc_fail_div`) — они устарели.

## Цель и сборка

RISC-V RV64 (`-march=rv64gc`), синтаксис GNU as, регистры по ABI-именам.
Сборка — `riscv64-linux-gnu-as` для нашего `.s` и рантайма, затем
`riscv64-linux-gnu-ld`, запуск — `qemu-riscv64`. Libc не линкуем: рантайм сам
делает системные вызовы. Всё это в `scripts/run.sh`.

## Значения

Любое значение — одно слово в 64 бита. `int` — без тегов, как есть.
`true` — 1, `false` и `()` — 0. Кортеж из n элементов — указатель на n слов
в куче. Замыкание — указатель на `[code | arity | argc | args…]`: адрес кода,
арность функции, число уже переданных аргументов и сами аргументы.

## Вызовы

Контракт System V для RISC-V: аргументы в `a0..a7`, остальные на стеке
вызывающего, результат в `a0`. Callee-saved — `s0..s11` и `sp`; `ra`
caller-saved: функция с вызовами сохраняет его сама. `sp` выровнен на 16.
Регистр `s10` — выделенный указатель кучи: его двигают runtime и inline-
аллокация кортежей. В отличие от обычных callee-saved регистров, его новое
значение должно быть видно вызывающему. Других применений `s10` нет.

## Символы

| Символ | Кто определяет | Что делает |
|---|---|---|
| `_start` | рантайм | инициализирует `gp`, выделяет кучу (`HEAP_SIZE`, 1 МиБ, без роста), вызывает `vc_main`, завершает процесс с кодом 0 |
| `vc_main` | наш код | верхний уровень программы |
| `vc_closure(code, arity)` | рантайм | создаёт замыкание без аргументов |
| `vc_apply(closure, argc, argv)` | рантайм | применяет замыкание к `argc` аргументам из массива `argv` в памяти; не хватает аргументов — новое замыкание |
| `vc_print_int` | рантайм | печатает число из `a0` |
| `vc_print_newline` | рантайм | печатает перевод строки |
| `vc_fail(code)` | рантайм | печатает ошибку и завершает процесс с кодом 1; коды: 0 — деление на ноль, 1 — нет памяти |
| `vc_heap_end` | рантайм | неизменяемая верхняя граница кучи; inline-аллокации проверяют адрес конца нового блока |

Все символы рантайма начинаются с `vc_`, кроме `_start`; пользовательские
имена в сгенерированном коде не должны с ним совпасть.

## Почему так

Без тегов арифметика — одна инструкция, а сборщика мусора, которому нужно
отличать указатели, у нас нет. `s10` под кучу избавляет от глобальной
переменной и загрузки адреса на каждое выделение.

## Кодогенерация (#21)

`Codegen.generate` принимает уменьшенную ANF и возвращает `Riscv.program`.
В AST из #19 метки и директивы отделены от машинных инструкций, поэтому
здесь нужен `item list`, а не старый черновой `instr list` из текста #21.

Каждый параметр и ALet получает слот относительно входного `s0/fp`.
Кадр выделяется одним `addi`, сохраняет `ra` и прежний `s0` и содержит
отдельную область исходящих аргументов/argv. Большие кадры (>2032 байт)
отвергаются через `Error` до печати imm12. Первые восемь аргументов идут
в регистры, остальные — в `0(sp)`, `8(sp)` и далее. Прямой полный вызов
известной функции не обращается к `vc_apply`.

Глобальные значения вычисляются в `vc_main` в исходном порядке и записываются
в `.data`. Для функции как значения используется статическое замыкание,
для неполного/неизвестного вызова — `vc_apply`. Встроенные операции как
значения получают маленькие обёртки; обычная арифметика всегда инлайн.
`vc_print_int` сам возвращает `unit = 0`, а не результат системного вызова
`write`; это сохраняется и при использовании печати как функции первого класса.

Каждая ветка `CIf` пишет в один слот результата или в `a0`, после чего
сходится на общей метке. Продолжение в ветки не дублируется. Тест размера
проверяет линейный рост цепочки условий. Сравнения работают над словами:
целыми и bool; структурного сравнения кортежей без типов здесь нет.

При интеграции обнаружились два требования автономного runtime, которые
не видны из C-тестов: `gp` должен быть настроен без libc/crt0, и загрузка
регистровых аргументов не должна сдвигать выровненный `sp`. Ручной assembly-
тест проверяет нечётные арности, стековые аргументы и избыточное применение.
Одна страница кучи недостаточна для CPS-Фибоначчи: 1 МиБ покрывает примеры,
а явная граница предотвращает выход за mmap даже при отображённом соседе.
