# Оба парсера принимают общее ядро и разбирают его как OCaml

У нас два парсера — нисходящий (`lib/rd_parser.ml`, №2) и восходящий на
menhir + ocamllex (`lib/menhir_parser.mly`, `lib/menhir_lexer.mll`,
`lib/menhir_frontend.ml`, №3). Оба принимают **одно и то же множество
программ** и строят **одно и то же дерево**.

Эталон — сам OCaml: всё, что принято, — корректный OCaml и даёт то же дерево,
что настоящий парсер из `compiler-libs` (`test/reparse.ml` — оракул в тестах).
Всё вне ядра — `Error` в обоих парсерах.

Раньше целились в широкое подмножество (все классы операторов, `begin … end`,
`;;`, шестнадцатеричные литералы). Нисходящий парсер этого не умел, поэтому
сузили до общего ядра. ТЗ хватает CPS-факториала и фибоначчи, ядро чуть шире.

Лексика общая — `lib/lexicon.ml` (приватный модуль): зарезервированные слова,
операторы и тексты лексических ошибок.

Раз множество программ одно, бенчмарк №5 сравнивает парсеры на одинаковом
входе — программах из ядра, которые принимают оба.

## Структура и выражения

* Программа — только `let` / `let rec` с `and`. `;;` не поддерживается.
* Выражения: целые, `true`, `false`, `()`, идентификаторы, оператор в скобках
  `( + )` (это имя), применение, бинарные операторы, унарный минус,
  `let … in`, `fun`, `if … then … else` (`else` обязателен), кортежи без
  скобок, скобки.
* `let f x y = e` сахарится в `Expr_fun`. Параметры — только после имени
  (`f` или `( + )`): `let (x) y = …`, `let _ x = …`, `let (a, b) x = …` —
  ошибка, как в OCaml.
* Кортежи без скобок — как в OCaml: тело `let … in`, `fun` и ветка `else`
  тянутся вправо через запятую. `fun x -> x, x` = `fun x -> (x, x)`,
  `if a then b else c, d` = `if a then b else (c, d)`. Элементы кортежа сами
  не бывают кортежами без скобок.
* `let`, `fun`, `if` не бывают операндом или аргументом: `1 + if …`,
  `1 + let … in …`, `- if …`, `f fun x -> x` — ошибка, нужны скобки.
* `true`, `false`, `()` без скобок не бывают функцией: `true x`, `() x` —
  ошибка (OCaml считает их конструкторами и отвергает `true x y`). `(true) x`
  и `f true ()` — можно. Принтер печатает такую функцию в скобках
  (`(true) 1`), иначе вывод вышел бы за ядро.
* Комментарии вложенные.

## Операторы

От слабого к сильному, приоритет и ассоциативность как в OCaml:

| Операторы                         | Ассоциативность |
|-----------------------------------|-----------------|
| `\|\|`                            | правая          |
| `&&`                              | правая          |
| `= <> < <= > >=`                  | левая           |
| `+ - +. -.`                       | левая           |
| `* / *. /. mod land lor lxor`     | левая           |
| `** lsl lsr asr`                  | правая          |

* Унарный минус сильнее всех бинарных, но слабее применения:
  `-f x` = `~-(f x)`, `-x ** 2` = `(-x) ** 2`.
* Операторы вне таблицы (`@ ^ |> @@ := != & !x ~-` и т. п.) — лексическая
  ошибка «оператор … вне подмножества». `#` не символ оператора: «неожиданный
  символ '#'». `+`, `-.`, `+.` в унарной позиции (`+x`, `-.x`, `+.x`) —
  синтаксическая ошибка.
* Оператор читается целиком, как в OCaml: `1+-1` — оператор `+-`, ошибка.

## Унарный минус

* `-e` → `Expr_app (Expr_ident "~-", e)`. Унарных `+`, `-.`, `+.` нет.
* Минус перед целой константой сворачивается в `Const_int`. Скобки прозрачны:
  `-(1)` — константа, `-(-1)` = 1.
* `-4611686018427387904` (и `- 4611686018427387904`) — константа `min_int`.
  Модуль `4611686018427387904` допустим только сразу после минуса:
  `-(4611686018427387904)` и голое `4611686018427387904` — ошибка.
* Известное отличие: `-(-4611686018427387904)` и `- - 4611686018427387904` у
  нас дают `min_int`, OCaml их отвергает. Оставили.

## Паттерны

* Переменная, `_`, целая константа, `true`/`false`, `()`, оператор в скобках.
* Отрицательная константа — только в скобках: `(-1)`. `let -1 = …`,
  `fun -1 -> …` и `(-1, 2)` — ошибка.
* Кортежи: без скобок — на верхнем уровне связывания (`let a, b = …`), в
  параметрах `fun` — только в скобках.

## Лексика

* Литералы — только десятичные цифры. `0x1F`, `0o7`, `0b1`, `1_000`, `1.5`,
  `1L`, `1x` — ошибка «литерал … вне подмножества: только целые» (для OCaml
  это один литерал, а не число и что-то следом). Переполнение — ошибка.
* Идентификаторы — с маленькой буквы или `_`, дальше буквы, цифры, `_`, `'`.
  Заглавные (конструкторы и модули: `Some`, `List.map`) — ошибка.
* Все ключевые слова OCaml вне ядра, включая `begin`, `end`, `or`, `match`,
  зарезервированы: ошибка «ключевое слово … вне подмножества», а не
  идентификатор.

## Ошибки

* `Error "строка:колонка: описание"`, колонка с 1. Исключения наружу не
  выходят.
* Одинаковый текст в обоих парсерах:
  * лексические ошибки (ключевое слово, конструктор, оператор, литерал,
    неожиданный символ, переполнение, незакрытый комментарий). Сюда же модуль
    `min_int` не после минуса (`4611686018427387904`,
    `-(4611686018427387904)` — «целое … не помещается в int»); в menhir это
    ловит `menhir_frontend`, лексер отдаёт токен `INT_MIN_ABS`;
  * «неожиданный конец ввода», если ошибка найдена на конце ввода. После
    оператора в скобках (кроме минуса) оба сразу ждут `)`: `( mod` —
    «1:6: неожиданный конец ввода».
* Синтаксические ошибки: текст у каждого свой, позиция тоже может отличаться —
  парсеры замечают ошибку на разных токенах. Формат «строка:колонка» общий.

## Тесты

* `test/parsers_test.ml` гоняет всё через оба парсера: эталоны, round-trip
  принтера, сравнение с оракулом, известное отличие `min_int`, точные тексты
  общих ошибок, входы вне ядра (ошибка с позицией).
* `test/rd_parser_test.ml` — отдельные тесты нисходящего парсера.
* `test/cli.t` — cram-тест драйвера: гоняет настоящий `vibecamlc` (выбор
  парсера, `--dump-ast` / `--dump-pp`, stdin и `-`, ошибки на `--ext-*`).
* `test/parsers_qcheck_test.ml` — QuickCheck (№4): `parse (pp ast) = ast` для
  обоих парсеров, по 1000 случайных выражений и программ. Генераторы и shrink
  — `test/generate.ml`: имена из ядра для парсеров, пошире (с операторами вне
  ядра) — для `test/pprint_test.ml`, где принтер сверяется с оракулом. Seed
  случайный и печатается при падении; повтор — `QCHECK_SEED=<seed> make test`.
* Принтер (`lib/pprint.ml`) печатает операторы ядра инфиксно с минимумом
  скобок по таблице выше, остальные — префиксно (`( @@ ) f x`).
* Разово прогнан дифференциальный фаззинг: 1,5 млн случайных строк из токенов
  ядра. menhir, rd и OCaml совпали везде, кроме отличия с `min_int`. В
  репозитории его нет.

## Отложено

Открытые вопросы, подробности — в тикетах.

* `--ext-*` пока дают ошибку и код 1. В rd — «расширение --ext-… пока не
  реализовано», реализация — №5. В menhir — «расширение --ext-… не
  поддерживается в menhir-парсере». Если флагов два, сообщение про первый.
* Принтер растёт нелинейно на длинных цепочках операторов: 100 тыс. — 0,7 с,
  200 тыс. — 2,2 с, 400 тыс. — 6,7 с. Причина не выяснена. На реальных
  программах не проявляется.
* Zanuda: алерты на сгенерированный menhir-код (глушится только `.zanuda` в
  корне, он не наш) и на `mutable index` в rd.
