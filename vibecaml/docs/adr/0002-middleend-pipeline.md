# 0002. Контракт middleend и решения для ANF

Статус: принятые договорённости из задач #9 и #12. `Fresh`, lambda lifting,
rename, closure conversion, ANF, уменьшение и CLI соединены.

## Конвейер

`parse → rename → closure conversion → lambda lifting → ANF → уменьшение ANF`.

До ANF используем `Ast`: каждый проход можно проверить отдельно, напечатать
через `Pprint` и выполнить результат в OCaml. ANF строим последней, потому что
после lambda lifting видны определения глобальных функций и их арность.

После rename связанные имена уникальны во всей программе, включая параметры
соседних функций. Для этого список занятых имён отделён от окружения видимых
имён. Первое обычное имя сохраняется, повторные получают новое. Пользовательские
операторы получают имя `op__N`, а имена с `__` всегда переименовываются.
После closure conversion у функции
нет свободных локальных переменных: они переданы явно. После lambda lifting
`Expr_fun` допускается только справа от верхнеуровневого `let` с именем или `_`.
В нерекурсивном `let _ = fun ...` ANF даёт функции свежее имя, сохраняя параметры
и тело. Само тело при объявлении не выполняется. Рекурсивная группа требует
именованных функций, чтобы её члены могли обращаться друг к другу.
Локальные рекурсивные группы не поддерживаются: closure conversion возвращает
`Error`, как оговорено в задаче #10. Rename умеет переименовать такую группу,
но это не означает поддержку её дальнейшего преобразования.

Глобальные имена — объявления верхнего уровня и `Lexicon.builtins`
(операторы, `~-`, `print_int`). Нерекурсивное объявление видит предыдущие
глобальные имена, рекурсивное — также свою группу. Арность непосредственно
определённой функции равна числу паттернов
в её `Expr_fun`. У бинарных операторов арность 2, у `~-` и `print_int` — 1.
У параметров, локальных переменных и глобальных псевдонимов она неизвестна.
Переопределение оператора убирает его статус встроенного в соответствующей
области видимости. Нерекурсивное объявление не видит себя и соседние RHS,
рекурсивная группа функций видит всю группу.

## Новые имена и подключение

Все проходы должны получать имена из общего `Fresh.name`: один счётчик,
формат `base__N`. Сброс нужен только перед всей программой или отдельным тестом,
а не между проходами. Уточнение из #10: все пользовательские связанные имена
с `__` переименовываются, поэтому зарезервированные имена проходов не занимают
повторно. Вход должен быть корректным OCaml: неизвестные свободные имена
не становятся объявлениями автоматически.

CC передаёт захваты первыми аргументами в алфавитном порядке. Каждому
добавленному параметру даётся новое имя `capture__N`; обращения к захваченной
переменной внутри тела, включая вложенные функции, заменяются этим именем.
В месте частичного применения остаётся исходное имя переменной. Это сохраняет
контракт уникальности после CC, а не только после rename. Нерекурсивный
локальный `let ... and ...` не связывает имена группы в своих RHS.

После мержа PR #10 общий `Fresh` доступен в библиотеке. ANF пользуется им
напрямую, а `Fresh.reset ()` вызывается один раз перед всей программой.
Подключение выглядит так:

```ocaml
match Anf_conv.convert lifted_program with
| Error message -> (* сообщить об ошибке через драйвер *) Error message
| Ok program -> Ok (Anf_simplify.simplify program)
```

Результат печатается через `Anf.pp_program` или `Anf.string_of_program`.
Тестовый драйвер в `test/anf/fixture.ml` использует общий `Fresh` и уже поднятые
вручную CPS-программы. Основной CLI по умолчанию и с `--stop-after anf` печатает
уменьшенную ANF; `--stop-after parsing`, `rename`, `cc` и `ll` печатают
соответствующий `Ast`. Перед lambda lifting всегда выполняются rename и CC,
поэтому исходные CPS-программы вручную замыкать больше не требуется.
Прямой вызов модулей по-прежнему требует соблюдения их входных контрактов.

## Условное выражение как действие

Разрешаем `CIf` внутри `cexpr`, то есть `let t = if ... then ... else ... in ...`.
В строгом варианте ANF из лекции условие — оператор, поэтому это осознанное
расширение. В будущем RISC-V каждая ветка запишет результат в ячейку `t`, после
чего выполнение продолжится с общим хвостом.

Альтернатива — подставить продолжение в обе ветки: при вложенных условиях это
может сильно увеличить программу. Другая альтернатива — вынести продолжение
в отдельную функцию, но тогда понадобятся новые функции после lambda lifting.
Для первого бэкенда связывание результата проще и сохраняет линейный размер.

Встроенное сравнение целых можно оставить в `CondCmp`, чтобы затем выбрать
инструкцию «сравнить и перейти». Типов в `Ast` пока нет, поэтому применяем это
правило, когда хотя бы один операнд — целая константа или результат встроенной
целочисленной операции. На корректно типизированном входе второй тоже целый.
Сравнения с неизвестным типом, булевы сравнения и переопределённые операторы
остаются `CApp` с `CondImm`; после вывода типов условие можно будет расширить.

## Вычисления и уменьшение

Известная арность позволяет собрать `f a b` в один `CApp`. Частичное применение
передаёт имеющиеся аргументы, лишние применяются к результату по одному.
Неизвестная функция всегда получает один аргумент за вызов. Аргументы и
элементы кортежа вычисляются справа налево, как в OCaml 5.5.1; RHS группы
`let ... and ...` — слева направо. Язык OCaml не обещает этот порядок между
разными реализациями, здесь фиксируем поведение инструмента из CI.
Встроенные `&&` и `||` превращаются в `CIf`, сохраняя короткое замыкание.

Уменьшение — отдельный модуль `Anf_simplify`: подстановка атомов и удаление
связывания результата в хвосте. Неиспользуемые вызовы сохраняем: они могут
иметь эффекты. В подготовленных CPS-примерах число локальных `ALet` уменьшается
с 9 до 3 для `fack`, с 12 до 5 для `fibk`. Это закреплено в cram-тесте.

## Кортежные поля и исполняемая печать

Паттерн параметра заменяется одним именем, а его элементы извлекаются `CField`.
Вложенный кортеж остаётся одним аргументом, его поля извлекаются отдельно.
`_` и `()` не связывают переменную, но вычисление RHS сохраняется.
Числовые и булевы паттерны пока возвращают понятную ошибку: для них нужен
контроль неуспешного сопоставления, которого в выбранном ANF нет.

После ревью расширяем тип из #12 до `CField (atom, index, size)`. Размер
известен при разборе кортежного паттерна, включая его вложенные части. Принтер
строит паттерн ровно этого размера: например, поле 1 тройки печатается как
`(let (_, anf_field, _) = t in anf_field)`. Это обычный типобезопасный OCaml,
без `Obj`. Локальное имя `anf_field` видно только в теле этого маленького `let`,
а атом `t` вычисляется до его связывания, поэтому пользовательская переменная
с таким же именем не захватывается. Для бэкенда `CField` останется чтением по
смещению; дополнительный размер пригодится для проверки индекса.

Структурные тесты проверяют уникальность связанных имён после rename, CC
и lifting, а также отсутствие локальных свободных переменных в каждой `fun`.
Сквозной CLI-тест прогоняет 16 обычных исходников с обоими парсерами через
rename, CC, lifting и ANF: всего 128 сравнений со stdout исходного OCaml.
Проверяются реальные CPS-программы, захваты, затенение, взаимная рекурсия,
кортежные паттерны, операторы, эффекты и пользовательские имена с `__`.

Тесты выполняют исходник, ANF до уменьшения и ANF после уменьшения настоящим
`ocaml`, сравнивая весь stdout, включая побочные эффекты. `ocaml` входит в
установленный компилятор из CI; dune явно указывает его как зависимость теста.
