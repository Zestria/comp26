# Backend RISC-V 64

Реализованы задачи разработчика B (3–6): представление и печать ассемблера,
стековые кадры, выражения и глобальные инициализаторы, прямые вызовы и обращения
к runtime замыканий. Библиотека `BDSMl.backend` пока не подключена к CLI
(это задача 9). Основные решения по ABI записаны в [abi/ABI.md](abi/ABI.md):
Linux RV64GC, стандартный ABI `lp64d`, значения по 64 бита. Объявления runtime
находятся в [runtime.h](../runtime/runtime.h). Общие константы доступны через
`BDSMl_backend.Abi`.

Публичная точка входа:

```ocaml
val BDSMl_backend.Codegen.generate :
  BDSMl_middleend.Anf.Anf_ast.aprogram -> (string, string) result
```

Вход — структура ANF после alpha, normalize_rec, closure conversion и lambda
lifting. Backend не разбирает напечатанный OCaml. Привязки должны иметь
уникальные имена, `&&`/`||` должны быть переведены в `CIf`. Ошибки неизвестных
имён возвращаются через `Error`; частичный результат не публикуется.
Единственная встроенная функция — `print_int`. Состояние меток и символов
создаётся заново при каждом вызове `generate`, поэтому вывод воспроизводим.

| Файл | Назначение | Задача |
|---|---|---|
| `abi/abi.ml/.mli` | представление значений, аргументы, результат, сохраняемые регистры | 0 |
| `assembly/asm.ml/.mli` | регистры, инструкции, операнды, метки и директивы | 3 |
| `assembly/asm_printer.ml/.mli` | печать GNU-совместимого ассемблера | 3 |
| `lowering/symbols.ml/.mli` | имена символов, метки, арности и глобальные определения | 3, 6 |
| `allocation/frame.ml/.mli` | размещение параметров и локальных значений, стековый кадр | 4 |
| `lowering/emit_expr.ml/.mli` | генерация операций, привязок и ветвлений ANF | 5 |
| `lowering/emit_call.ml/.mli` | прямые вызовы, функциональные значения, обращение к runtime | 6 |
| `codegen.ml/.mli` | сборка программы, глобальные инициализаторы и точка входа | 5, 9 |

## Кадры и вызовы

`sp` остаётся постоянным внутри функции и выровнен по 16 байтам. В нижней
части кадра находится область аргументов максимального вызова в теле;
затем временные слоты, параметры и локальные привязки, в конце — сохранённый
`ra`. Регистры `s0`–`s11` не используются, сохранять их не требуется. Слоты
параметров и локальных значений не перекрываются с областью вызовов, поэтому
вложенные вызовы и выделение замыканий их не повреждают. Пока используется
стековое размещение; Linear Scan остаётся дальнейшим улучшением из ABI.md.

При прямом вызове с простыми аргументами значения сразу загружаются в
`a0`–`a7` и исходящие стековые слоты. Если аргумент требует создания замыкания,
аргументы сначала сохраняются в кадре и лишь затем загружаются в регистры:
создание второго замыкания не должно уничтожить первый аргумент.
При косвенном вызове эта же область служит
массивом `argv` для `bd_apply`; указатель на вызываемое замыкание сохраняется
отдельно. Частичное применение и избыток аргументов обрабатывает runtime.
Точный вызов известной функции не создаёт замыкания.

Большие константы/адреса загружаются через `li`/`la`. Для смещений за пределами
знакового 12-битного поля `Asm` строит адрес через резервный `t6`; это
распространяется и на большой кадр, и на аргументы за регистровым лимитом.
Ветви `CIf` сходятся в одной метке без дублирования продолжения.

Глобальные значения находятся в `.bss`. `main` вычисляет инициализаторы и
`AEval` в порядке ANF и возвращает код 0. Деление проверяет нулевой делитель
до `div`, вызывая `bd_division_by_zero` только на ветке ошибки.

## Проверки задач B

Из корня репозитория:

```sh
opam exec --switch=comp26 -- dune build -p BDSMl
opam exec --switch=comp26 -- dune runtest BDSMl/test
```

Нужны `riscv64-linux-gnu-gcc`, статическая RISC-V libc, `qemu-riscv64` и
`timeout` (установка описана в ABI.md). Отсутствие инструментов считается
ошибкой теста: проверки QEMU не пропускаются молча.

[backend_tests.ml](../test/backend_tests.ml) проверяет арифметику, знаковые
сравнения и переполнение, ветвления, эффекты, глобальные значения, прямые и
косвенные вызовы, частичное применение, избыток аргументов, рекурсию с захватом,
передачу `print_int` как значения и большие кадры с 300 аргументами. CPS-факториал
печатает `120`, CPS-Фибоначчи — `55`. Каждый запуск QEMU ограничен 10 секундами.

Runtime задач 7–8 пока остаётся в заглушках. Для независимой проверки backend
тесты линкуют **только тестовые** реализации из `test/backend_support/`:
простой двойник контракта и ассемблерный адаптер RV64. Они не входят в
production runtime, не предназначены для использования компилятором и не
заменяют обработку ошибок выделения памяти, которую должен добавить C.
После реализации C интеграционные тесты должны линковать его runtime.
Команда итоговой сборки ELF с production runtime описана в ABI.md.

Каталоги объединяют общие задачи: `abi/` — соглашения, `assembly/` —
представление и печать ассемблера, `allocation/` — размещение значений,
`lowering/` — перевод ANF в инструкции. `Codegen` остаётся точкой входа.
Dune использует `include_subdirs qualified`, как frontend и middleend:
например, принтер доступен как `BDSMl_backend.Assembly.Asm_printer`.
