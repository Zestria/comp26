# Backend RISC-V 64

Реализованы представление и печать ассемблера, стековые кадры, выражения,
глобальные инициализаторы, прямые вызовы и runtime замыканий. Библиотека
`BDSMl.backend` подключена к CLI: обычная компиляция выдаёт RV64-ассемблер.
Основные решения по ABI записаны в [abi/ABI.md](abi/ABI.md):
Linux RV64GC, стандартный ABI `lp64d`, значения по 64 бита. Объявления runtime
находятся в [runtime.h](../runtime/runtime.h). Общие константы доступны через
`BDSMl_backend.Abi`.

Из корня репозитория:

```sh
dune exec BDSMl/compiler.exe -- program.ml -o program.s
dune exec BDSMl/compiler.exe -- -parsing menhir program.ml -o program.s
dune exec BDSMl/compiler.exe -- --stop-after anf program.ml -o -
```

Без `--stop-after` выводится GNU-совместимый ассемблер. По умолчанию результат
идёт в stdout; `-o FILE` записывает файл, `-o -` явно выбирает stdout.
Сборка ELF с runtime и запуск QEMU описаны в [abi/ABI.md](abi/ABI.md).
`--parse` сохраняет вывод AST для исходника из командной строки.
Ошибки компиляции идут в stderr с кодом 2; выходной файл открывается
только после успешного получения полного результата генерации.

Публичная точка входа:

```ocaml
val BDSMl_backend.Codegen.generate :
  BDSMl_middleend.Anf.Anf_ast.aprogram -> (string, string) result
```

Вход — структура ANF после alpha, normalize_rec, closure conversion и lambda
lifting. Backend не разбирает напечатанный OCaml. Привязки должны иметь
уникальные имена, `&&`/`||` должны быть переведены в `CIf`. Ошибки неизвестных
имён возвращаются через `Error`; частичный результат не публикуется.
Единственная встроенная функция — `print_int`. Состояние меток и символов
создаётся заново при каждом вызове `generate`, поэтому вывод воспроизводим.

| Файл | Назначение |
|---|---|
| `abi/abi.ml/.mli` | представление значений, аргументы, результат, сохраняемые регистры |
| `assembly/asm.ml/.mli` | регистры, инструкции, операнды, метки и директивы |
| `assembly/asm_printer.ml/.mli` | печать GNU-совместимого ассемблера |
| `assembly/optimize.ml/.mli` | локальное удаление лишних инструкций |
| `lowering/symbols.ml/.mli` | имена символов, метки, арности и глобальные определения |
| `allocation/frame.ml/.mli` | размещение параметров и локальных значений, стековый кадр |
| `lowering/emit_expr.ml/.mli` | генерация операций, привязок и ветвлений ANF |
| `lowering/emit_call.ml/.mli` | прямые вызовы, функциональные значения, обращение к runtime |
| `codegen.ml/.mli` | сборка программы, глобальные инициализаторы и точка входа |

## Кадры и вызовы

`sp` остаётся постоянным внутри функции и выровнен по 16 байтам. В нижней
части кадра находится область аргументов максимального вызова в теле;
затем временные слоты, параметры и локальные привязки, в конце — сохранённый
`ra`. Регистры `s0`–`s11` не используются, сохранять их не требуется. Слоты
параметров и локальных значений не перекрываются с областью вызовов, поэтому
вложенные вызовы и выделение замыканий их не повреждают. Пока используется
стековое размещение; Linear Scan остаётся дальнейшим улучшением из ABI.md.

При прямом вызове с простыми аргументами значения сразу загружаются в
`a0`–`a7` и исходящие стековые слоты. Если аргумент требует создания замыкания,
аргументы сначала сохраняются в кадре и лишь затем загружаются в регистры:
создание второго замыкания не должно уничтожить первый аргумент.
При косвенном вызове эта же область служит
массивом `argv` для `bd_apply`; указатель на вызываемое замыкание сохраняется
отдельно. Частичное применение и избыток аргументов обрабатывает runtime.
Точный вызов известной функции не создаёт замыкания.

Большие константы/адреса загружаются через `li`/`la`. Для смещений за пределами
знакового 12-битного поля `Asm` строит адрес через резервный `t6`; это
распространяется и на большой кадр, и на аргументы за регистровым лимитом.
Ветви `CIf` сходятся в одной метке без дублирования продолжения.

Генерация инструкций использует неизменяемое состояние `Asm.code`: список
инструкций и счётчик меток передаются через `let*`, без изменяемых полей.
`Asm.finish` начинает независимую генерацию; таблица символов также неизменяема.

Перед печатью `Assembly.Optimize` убирает загрузку сразу после записи в ту же
ячейку (заменяя её пересылкой из регистра), пересылки регистра в себя,
прибавление нуля и переход к следующей метке. В функциях без вызовов убираются
обычные стековые сохранения и восстановления `ra`. Упрощения не переносят
значения через метки или вызовы и не меняют размеры кадров. Это локальная
очистка; обязательный будущий Linear Scan пока не реализован.

Глобальные значения находятся в `.bss`. `main` вычисляет инициализаторы и
`AEval` в порядке ANF и возвращает код 0. Деление проверяет нулевой делитель
до `div`, вызывая `bd_division_by_zero` только на ветке ошибки.

## Проверки

Из корня репозитория:

```sh
opam exec --switch=comp26 -- dune build -p BDSMl
opam exec --switch=comp26 -- dune test -p BDSMl
opam exec -- zanuda -dir BDSMl
```

Проверено на OCaml 5.5.1: сборка, тесты и Zanuda проходят без замечаний.
После локальной очистки число инструкций в CPS-факториале уменьшилось
с 89 до 83, в CPS-Фибоначчи — со 129 до 123 (счёт по строкам инструкций,
включая псевдоинструкции, без директив и меток).

Нужны `riscv64-linux-gnu-gcc`, статическая RISC-V libc, `qemu-riscv64` и
`timeout` (установка описана в ABI.md). Отсутствие инструментов считается
ошибкой теста: проверки QEMU не пропускаются молча.

[backend_tests.ml](../test/backend_tests.ml) проверяет арифметику, знаковые
сравнения и переполнение, ветвления, эффекты, глобальные значения, прямые и
косвенные вызовы, частичное применение, избыток аргументов, рекурсию с захватом,
передачу `print_int` как значения и большие кадры с 300 аргументами. CPS-факториал
печатает `120`, CPS-Фибоначчи — `55`. Каждый запуск QEMU ограничен 10 секундами.

Тесты линкуют production runtime из `runtime/`: создание и применение
замыканий, адаптер RV64 ABI, `print_int` и ошибку деления на ноль.
Команда сборки ELF с runtime описана в ABI.md.

[check_riscv.sh](../bin/check_riscv.sh) дополнительно проверяет полный путь
через CLI для `print_int`, CPS-факториала и CPS-Фибоначчи с обоими парсерами:
исходник → CLI → ассемблер → GCC с runtime → ELF → QEMU. stdout сравнивается
побайтово с OCaml и ответами `42`, `120`, `55`, stderr должен быть пустым,
каждый шаг должен завершиться с кодом 0. Ограничения времени: 10 секунд
для OCaml, компилятора и QEMU, 30 секунд для GCC. Проверка входит в cram-тест
`bin/run.t` и запускается командой `dune test -p BDSMl`.

Структура каталогов: `abi/` — соглашения, `assembly/` —
представление и печать ассемблера, `allocation/` — размещение значений,
`lowering/` — перевод ANF в инструкции. `Codegen` остаётся точкой входа.
Dune использует `include_subdirs qualified`, как frontend и middleend:
например, принтер доступен как `BDSMl_backend.Assembly.Asm_printer`.
