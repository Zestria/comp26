# Фронтенд

Оба парсера строят общее дерево `Ast.program`:

| Реализация | Лексер | Входная функция |
| --- | --- | --- |
| Рекурсивный спуск | `lexer.ml` | `Parser_LL.parse_string_LL` |
| Menhir + ocamllex | `lexer_LR.mll` | `Parse.parse` |

`lexer.ml` — ручной лексер одногруппника. `lexer_LR.mll` — прежний `lexer.mll`,
адаптированный к его токенам. Суффикс `_LR` позволяет собирать обе реализации
в одной директории: ocamllex создаёт `lexer_LR.ml`, не конфликтуя с `lexer.ml`.

Грамматика Menhir находится в `parser.mly`. Она использует общий тип
`Lexer.token` через `--external-tokens Lexer`: `TInt`, `TIdent`, `TUnit`, `TIF`
и остальные токены имеют те же имена и типы, что в нисходящем парсере.
`Lexer_LR.tokenize` возвращает такой же список токенов, включая `TEOF`.
`Parse.parse` напрямую запускает Menhir с лексером ocamllex и возвращает ошибки
как строки, сохраняя прежний интерфейс `(Ast.program, string) result`.

В `parser.mly` сохранены исходные правила и приоритеты Menhir; имена токенов
приведены к `Lexer.token`, а `PWild` заменён на новый узел AST `PUnderscore`.
Добавлен разбор токена `TUnit`. Как и прежде, восходящий парсер допускает пустую
программу, соседние определения `let` без `;;` и unit с пробелом `( )`.
В лексере ocamllex сохранена поддержка вложенных комментариев `(* ... *)`.

Из корня репозитория (нужны Dune >= 3.24 и зависимости проекта):

```sh
dune build BDSMl/frontend/frontend.cma
dune runtest BDSMl/test
```

Тесты сравнивают токены и AST обоих вариантов, проверяют CPS-факториал,
CPS-Фибоначчи, приоритеты, ошибки и 4000 случайных примеров QCheck.
